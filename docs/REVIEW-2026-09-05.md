# App review — 2026-09-05

## Scope and approach

Resumed the uncommitted `fix/security-validation-review` branch after an interrupted
review. The branch starts at the current consolidated main (`3bd66ab`). Reviewed
and completed the existing security, TaskProcessing, localization and frontend
changes. Work ran sequentially with low-priority, single-process builds and a
640 MiB V8 heap limit; no indexing runs or model inference were started.

## Changes

- Replace path-based deletion grants with versioned file-ID grants. Reject legacy
  paths, prune missing identities, preserve grants through renames, and never
  claim ownership merely by editing an existing file or using an existing folder.
- Separate native Assistant proposals, explicitly confirmed actions and read-only
  chat policy surfaces. Bound supplied memories and preserve the user's prompt.
- Treat retrieved files and personal knowledge as untrusted model context rather
  than system instructions. Require authenticated per-user model lookup.
- Cap interleaved document chunks independently; escape mail search wildcards and
  bound result counts. Require a current file node for cached RAG file access.
- Ship matching English/German JSON and legacy JS translation catalogs, check their
  placeholders and literal frontend keys, and load them in each frontend entry.
- Wire standalone export and empty-chat rendering. Generate Files action links
  through the router and open batch selections in one shared file context.
- Add a low-memory webpack mode, explicitly handle SAX's optional Node stream
  dependency, and align `.nvmrc`/package engines with Node 24 and npm >=10.5.

## Limits and follow-up

These checks do not establish that the entire application is error-free. The
local Nextcloud is a release candidate, and only the locally installed PHP was
executed here; GitHub CI covers its configured PHP versions separately.

No authenticated browser session was available. Live Ollama, streaming, actual
native Assistant proposal/confirmation UI, Talk, notifications and indexing were
not exercised (#133–#136 remain open). The JavaScript test mocks Nextcloud/browser
services and is not an end-to-end browser test. Some existing PHPUnit tests check
source contracts rather than runtime integration.

Native confirmation results are persisted before the optional model summary,
with a truthful fallback if it fails. Concurrent-confirmation and database-save
failure handling still need integration coverage. File-ID marker storage remains a
read/modify/write operation without a cross-request lock; concurrent marker writes
can lose grants. Neither should be interpreted as an exactly-once execution guarantee.

Issue #104 was subsequently implemented with CalDAV time-range prefiltering;
the historical verification result above predates that follow-up commit. Other
feature requests and issues were not assumed fixed merely because the local
suite passed. Discarding legacy
path grants deliberately means that older EVA-created files lose automatic
own-only deletion authorization.
